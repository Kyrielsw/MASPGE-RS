# iTransformer-InputMatched (adapted) 预训练审计与冻结协议

## 审计结论

旧 `itransformer_fullinfo_adapted` 不可直接作为当前同输入基线。它按旧 A1--A4 活跃角色提取槽位、拼接数据加载器的全局 `context`、仅以 `y_current` 作残差起点，并只输出一个未来均值 `[B,U]`。当前论文主模型则使用 60 步历史目标和通用逐单元传感器，预测完整 15 步序列，再用有效未来掩码计算序列训练损失与 horizon-mean MSE/MAE。因此直接复用会同时造成输入、输出和指标协议不一致。

## 冻结替代定义

唯一新增方法命名为 **iTransformer-InputMatched (adapted)**，明确是项目适配实现，不是原论文官方代码或官方复现结果。

- 输入：60 步历史目标及 MASPGE 实际消费的全部逐单元历史传感器槽位。
- 角色处理：仅按冻结存储合同展平槽位，不建立 A1--A4 编码器，不使用角色语义。
- `context`：四个数据文件均带有该张量，但当前 Generic Unit State 主模型的前向路径没有消费它；为严格同输入，新基线也不消费。MAFS 的 context gate 来自历史目标而非该张量。
- 输出：完整 `[B,15,U]` 预测；不输入未来传感器或未来上下文。
- 结构：每个物理单元为一个 token；token 由该单元的 60 步目标与传感器历史展平形成。两层、四头 Transformer，宽度 64，前馈宽度 128，dropout 0.1，15 步线性预测头。
- 训练：有效目标掩码下的完整序列 MSE；AdamW，学习率 `1e-3`，权重衰减 `1e-4`，梯度裁剪 1；最多 12 轮、至少 6 轮、耐心 3。
- 选模：只按验证集有效 horizon mean MSE；种子 42--46。
- 测试：四数据集 20 个验证运行齐全后，锁定配置与 checkpoint，由独立只读脚本统一评估。既有留出集已在项目研究中观察，因此只称事后公平性对照，不称全新盲测。

模型宽度与训练日程继承既有 `itransformer_power` 基线，未依据本次验证或留出结果搜索。各数据集只因冻结输入宽度、物理单元数及既有 batch 大小而自然产生参数量或计算量差异。若显存不足，只允许减小物理 batch 并以梯度累积保持有效 batch；必须记录该变化，不能改变模型或根据性能换基线。

## 数据与评价口径

四个数据集继续使用各自冻结的时间划分、训练集拟合归一化、边界规则、未来有效掩码与 60/15 协议。主要 MSE/MAE先对每个有效 window--unit 的 15 步有效目标求均值，再跨有效 pair 聚合；训练损失仍为逐时间点的 masked sequence MSE。验证脚本不构造 holdout dataset。

完成静态审计后，`verify_itransformer_input_matched_setup.py` 会对数据哈希、张量轴、有限值、窗口边界、split 顺序、槽位数和掩码存在性生成机器可读 `audit.json`。任何审计失败均应先停止，不得启动训练。
